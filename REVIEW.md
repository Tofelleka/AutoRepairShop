# Автосервис «Гараж Народный» — отчёт по замечаниям и соответствию ТЗ

Проект: консольная игра на .NET Framework 4.8.1 (C# 7.3), без внешних зависимостей.

---

## 1. Замечания ментора

| № | Замечание | Что сделано |
|---|---|---|
| 1 | `internal` у членов `internal`-класса не имеет смысла; стиль должен быть единым | Члены классов — только `public` / `private`. `internal` осталось только у объявлений самих классов (это видимость типа, она осмысленна) |
| 2 | `=>` вместо тела из одного выражения | `Count`, `HasCars`, `DequeueCar`, `GetAllDetails`, `TryGetDetail`, `ReplaceDetail`, `CanAfford`, `Apply`, `GetAll`, `RefuseRepairs`, `RefuseFurtherRepairs`, `Top/Middle/Bottom`, `DetailName`, `Center`, `Row(string)`, конструкторы `CashRegister`, `PartsFactory` |
| 3 | Классы не должны сами себя заполнять — передавать готовые наборы данных | `Car(string name, Dictionary<DetailType, Detail> details)`; `Warehouse(Dictionary<DetailType, List<Detail>> details)`. Генерация вынесена в `CarFactory`, `WarehouseFactory`, `PartsFactory`. Менеджер — единственный корень композиции |
| 4 | `SendPartToGarage` — склад не должен знать про гараж | Удалено. Склад умеет `bool TryTake(DetailType type, out Detail detail)` и `bool TryAdd(Detail detail)` |
| 5 | `CashRegister` не должен зависеть от `RepairReport` | `CashRegister` работает только с суммами: `CanAfford(decimal)`, `Apply(decimal)`, `Pay(decimal)`. Отчёт разбирает менеджер: `Apply(report.Total)` |
| 6 | Валидация параметров в `Warehouse` | `TryAdd` и `TryTake` возвращают `false` на неизвестный тип (нормальный исход), `GetQuantityDetail` бросает `ArgumentException` (ошибка вызывающего) |
| 7 | Порядок модификаторов и членов | Порядок: константы → поля → конструктор → публичные методы → приватные. Все классы приведены к нему |
| 8 | У `TryPay` не используется `return` | `TryPay` удалён. Разделено на «спросить» (`CanAfford`) и «сделать» (`Pay`, бросает `InvalidOperationException` при нехватке денег) |
| 9 | Захардкоженные значения меню | В `Illustrator` введены константы: `ExitCommand = 0`, `ConfirmCommand = 1`, `FirstItemNumber = 1`, `TakeCarCommand = 1`, `ShopCommand = 2`. Меню строится из них |
| 10 | `while (true)` в кодстайле не принято | Все циклы переписаны на явное условие (`bool isChosen`, `bool isAnswered`, `bool isNumber`). Ни одного `while (true)` в проекте |
| 11 | `ReplacementPart` — не по нотации | Переименовано в `Car.ReplaceDetail(Detail newDetail)` — глагол + объект |

Дополнительно (следствия из замечаний):

- `Car.GetAllDetails()` возвращает **копию** словаря и типизирован как `IReadOnlyDictionary` — внутреннее состояние не утекает;
- добавлен `Car.TryGetDetail(DetailType, out Detail)` — точечное чтение вместо копирования всего словаря;
- у конструкторов `Garage`, `PartsShop`, `Warehouse`, `CarsQueue`, `CarFactory`, `WarehouseFactory`, `PartsFactory` появились проверки на `null`;
- `Car` валидирует имя и набор деталей; `Warehouse` отклоняет начальный запас больше вместимости;
- удалён мёртвый код: `Utils`, `TryPay`, `DetailAvailable`, `SendPartToGarage`, `FillDetails` внутри `Car`/`Warehouse`, пустые `switch` в менеджере.

## 2. Соответствие ТЗ

| Требование ТЗ | Реализация |
|---|---|
| Автосервис содержит баланс денег | `CashRegister` (стартовый капитал 10 000) |
| Склад деталей | `Warehouse`, вместимость 60 |
| Очередь машин | `CarsQueue` (1–5 машин в день) |
| Машина состоит из деталей | `Car` — словарь «тип детали → деталь» |
| Поломанных деталей не меньше одной | `CarFactory`: случайные поломки с шансом 0.3, плюс страховка — если ни одна не сломалась, ломается случайная |
| Показывать все поломанные детали | Экран «ЧЕК-ЛИСТ ПОЧИНКИ»: название, описание поломки, выплата |
| Поломка чинится только заменой | `Garage.RepairDetail` — других способов ремонта нет |
| За раз можно заменять только одну деталь | Одна команда в чек-листе = одна замена |
| Успешная починка: цена детали + цена ремонта | `Detail.Payout = Price + ReplacementCost`, начисляется в `Garage` |
| Ремонт завершён, когда все детали исправны | Цикл менеджера: `while (car.CarIsBroken())` |
| От ремонта можно отказаться в любой момент | Отказ до ремонта (`0` на экране машины) и в процессе (`0` на экране выбора детали) |
| Отказ перед ремонтом — фиксированный штраф | `Garage.RefuseRepairs()` — 1 000 |
| Отказ во время ремонта — штраф за каждую непочиненную | `Garage.RefuseFurtherRepairs(...)` — 100 × число оставшихся сломанными |
| Количество деталей на складе ограничено | `Warehouse.WarehouseCapacity = 60`, `TryAdd` отказывает при заполнении |
| Замена целой детали: деталь пропадает со склада, выплаты нет | `RepairOutcome.ReplacedHealthy`, выплата 0, склад уменьшается (игрок может ошибиться — выбор идёт по полному списку склада) |
| За каждую удачную починку — выплата из чек-листа | В чек-листе показан `Payout`, начисляется ровно он |
| Класс `Detail` не содержит количества | В `Detail` только тип, имя, описание, цены, флаг поломки. Количество — в `Warehouse` (словарь списков) |

## 3. Проверки

Автоматические (детерминированный прогон домена с фейковым источником случайности, 13 проверок — все зелёные):

```
[ok] склад создаётся с 20 деталями
[ok] в каталоге 10 типов
[ok] ремонт сломанной: исход ReplacedBroken
[ok] ремонт сломанной: выплата = Payout
[ok] ремонт сломанной: склад -1
[ok] машина починена
[ok] исправная деталь: исход ReplacedHealthy
[ok] исправная деталь: выплата 0
[ok] исправная деталь: склад -1
[ok] покупка: исход Bought
[ok] покупка: деньги списаны
[ok] покупка: склад +1
[ok] 300 машин: у всех есть поломка
```

Ручные сценарии (прогон собранного exe):

- меню дня → машина → отказ (штраф 1 000, касса 9 000);
- чек-лист → замена сломанной детали (выплата, склад −1);
- замена исправной детали (выплата 0, склад −1);
- прерывание ремонта (штраф 100 × непочиненные);
- магазин: список 10 позиций с ценами и остатками, карточка с описанием, покупка (деньги −цена, склад +1).

## 4. Осознанные решения

- **Один namespace `AutoRepairShop`.** Папки (`Cars`, `Parts`, `Repairs`, `Factories`, `Enums`, `Game`, `UI`, `Common`, `Finance`) — навигация по проекту. Для сборки из 24 файлов отдельные namespace'ы дали бы только лишние `using`.
- **`Warehouse.TotalQuantity` оставлено с циклом.** `=>` здесь возможен только через LINQ (`Sum`), а LINQ пока не подключался осознанно.
- **Описание детали в магазине на отдельном экране-карточке.** Список из 10 позиций с двухстрочными описаниями не помещается в консоль; поэтому выбор номера открывает карточку с описанием, ценой, остатком и выплатой, а затем подтверждение покупки.
- **Штрафы 1 000 и 100 — константы `Garage`.** Это правила игры; при появлении уровней сложности они переедут в конфигурацию.

## 6. Модификации после приёмки

| Механика | Реализация |
|---|---|
| Аренда | `AutoRepairManager.DailyRent` (1 500), списывается в конце дня через `CashRegister.Apply(-rent)`; баланс может уйти в минус |
| Улучшения | `UpgradeType` (склад, реклама, квалификация), `UpgradeInfo` + `UpgradeCatalog` (3 уровня, цены), `ServiceDevelopment` (уровни по типу), `UpgradeShop.Buy(type)` |
| Эффекты | склад: `Warehouse.IncreaseCapacity`; реклама: максимум машин = 5 + уровень × 1; квалификация: выплата = цена + работа × (1 + 0.01 × 10 × уровень) |
| Цель смены | `GameGoal` (50 000 за 10 дней); поражение — касса в минусе; финал различает победу, срок, долг и выход игрока |
| Статистика дня | выручка, штрафы, чистая выручка, аренда, закупки, улучшения, прибыль |

Проверки: 17 детерминированных (каталог, уровни, цены, исходы покупки, надбавка к выплате, правило цели) + игровые сценарии (развитие, покупка, чек-лист с надбавкой, долг).

## 7. Цель «Дом», сохранения и статистика смены

- **Цель:** накопить 5 000 000 на дом; срок не ограничен, поражение — касса ушла в минус.
- **Экономика увеличена в 10 раз** (цены деталей, аренда, улучшения, стартовый капитал 100 000), чтобы 5 000 000 были достижимы примерно за 40–60 игровых дней, а не за триста.
- **Статистика смены** (дни, машины, ремонты, отказы, выручка, штрафы, аренда, закупки, улучшения, итог) показывается в финале и сохраняется между запусками.
- **Сохранение** — текстовый файл `save.txt` рядом с exe: деньги, номер дня, уровни улучшений, остатки склада, статистика смены. Запись в конце каждого дня, загрузка при старте.

## 8. Баланс под 200+ дней, тесты и сохранения

- **Экономика:** средняя работа за машину ~13 800 (30% поломок от суммы 46 100), 3 машины в день ~41 500, аренда 15 000 → ~26 500 в день. Цель 5 000 000 берётся за ~190 дней без улучшений и ~220 с полной прокачкой (1 050 000).
- **Тесты:** проект `AutoRepairShop.Tests` (32 проверки): машина, гараж (все исходы, штрафы, коэффициент), магазин, склад, улучшения, выплаты и округление, цель, сохранения. Раннер — свой (атрибут `[Test]` + рефлексия), без NuGet.
- **Сохранение:** атомарная запись через `save.txt.tmp` + `File.Replace`; при старте — выбор «продолжить / заново»; при выходе состояние сохраняется, при победе или поражении файл удаляется.

## 9. Производители, категории и новые сервисы

- **Производители:** три бренда (`Эконом`, `Стандарт`, `Премиум`) с коэффициентами цены, работы и вероятности поломки. Цена и работа детали считаются от шаблона: `базовая цена × коэффициент бренда`.
- **Категории:** двигатель (10 позиций), кузов (6), электрика (6), жидкости (3) — итого 25 шаблонов.
- **Магазины:** отдельный магазин на каждую категорию, выбор детали и производителя с подтверждением.
- **Боксы:** «Кузовной бокс» (400 000) и «Бокс электрика» (350 000) — одноуровневые улучшения, открывают соответствующие ремонты. Двигатель и жидкости доступны всегда.
- **Чек-лист** показывает производителя каждой детали и помечает заблокированные категории.
- **Сохранение** совместимо: новые типы читаются как 0, уровни новых боксов — как 0.
- **Тесты:** 40 проверок (добавлены бренды, категории, доступы, покупка по бренду).

## 10. Мета, бренды и события

- **Бренды:** NoName (дешевле, ломается чаще), АвтоВАЗ (базовый), Bosch (дороже, надёжнее и больше платят за работу).
- **Боксы:** «Кузовной бокс» и «Бокс электрика» — по три уровня, каждый +10% к работе соответствующей категории. Жидкости улучшений не имеют.
- **Риск дешёвых жидкостей:** при установке жидкости бренда NoName с шансом 35% ломается связанная деталь (масло → стартер, антифриз → радиатор, тормозная жидкость → передние ступичные).
- **Перекрас:** после покупки кузовного бокса с шансом 12% приходит заказ на полный перекрас (150 000). Бокс занят два дня, кузовные работы в это время недоступны.
- **Мета:** достижения (8 штук) и рекорд кассы хранятся в `profile.txt` отдельно от сохранения игры и переживают перезапуск.
- **Тесты:** 45 проверок.

## 11. Покраска, слоты, экран достижений и симулятор баланса

- **Материалы:** в кузовном магазине 4 краски, грунт и лак (6 позиций). Материалы не ставятся на машины — их расходует только перекрас.
- **Перекрас по цвету:** заказ приходит с конкретным цветом; нужны краска этого цвета, грунт и лак. Если покрасить в другой цвет — клиент не принимает работу, материалы сгорают, бокс всё равно занят два дня.
- **Слоты сохранений:** три файла `save1.txt`–`save3.txt`, выбор слота на старте.
- **Экран достижений:** пункт «4 - достижения» в меню дня, показывает открытые и закрытые достижения и рекорд кассы.
- **Баланс:** константы вынесены в `GameBalance` (аренда 18 000, цель 5 000 000). Симулятор на 200 дней даёт 178–214 дней до цели (среднее ~195) у «умного» бота; живой игрок медленнее.
- **Склад:** стартовая вместимость 80, чтобы хватало на 31 тип товаров.
- **Тесты:** 52 проверки, включая симулятор баланса.

## 12. Балансировка и обратная связь

- **Достижения:** «Художник» (покрасить не в тот цвет) и «Мастер перекраса» (3 успешных перекраса). Счётчик успешных перекрасов хранится в `profile.txt`.
- **Статус бокса:** в меню дня строка «Кузовной бокс: свободен / занят до дня N». В чек-листе заблокированные кузовные детали помечаются «бокс занят», а не «нужен бокс».
- **Симулятор с перекрасами:** бот учитывает перекрасы и занятость бокса.
- **Баланс:** аренда 20 000, перекрас 60 000, шанс перекраса 6%. Прогон на пяти сидах — 171–224 дня, среднее ~195.
- **Тесты:** 54 проверки, добавлены слоты сохранений (пути save1–save3, запрет слота 0 и 4).

## 13. Новые марки, курсы и боты баланса

- **Марки:** ВАЗ, Иж (Иж-2126, Иж-2715, Иж-2125), Волга (ГАЗ-24, ГАЗ-3102, ГАЗ-3110).
- **Уникальные детали:** у Ижа карбюратор, задний мост и рулевая рейка; у Волги водяной насос, гидроусилитель и рессоры.
- **Курсы:** «Курсы: Иж» открываются после 500 000 накоплений, «Курсы: Волга» — после 1 000 000. Стоимость 200 000 и 400 000. После прохождения марка начинает приезжать в сервис.
- **Сохранение:** хранит пройденные курсы и сумму накоплений.
- **Баланс:** склад на 150 мест, аренда 24 000. Умный бот проходит игру за 187–214 дней (среднее ~200), небрежные боты (sloppiness 0.2–0.4) — за 227–300 дней и не разоряются.
- **Тесты:** 65 проверок.

## 14. Магазины по маркам, модельные детали, особые поломки и ремонт без замены

- **Магазины:** три отдельных магазина запчастей (ВАЗ, Иж, Волга) плюс магазин материалов для покраски. В магазине марки только совместимые детали.
- **Модельные детали:** «Сцепление Самара» (2108/2109/2110/2114), «Трамблёр» (классика 2101–2107), «Борт фургона» (Иж-2715), «Форсунка» (ГАЗ-3110). Подбор деталей идёт по марке и модели.
- **Особые поломки:** у заднего моста Ижа своя вероятность 30% и надбавка +2 000, у ГУРа Волги — 8% и +3 000.
- **Ремонт без замены:** 9 типов деталей можно отремонтировать (радиатор, стартер, генератор, проводка, дверь, крыло, рейка Ижа, помпа Волги, сцепление Самары). Вариант выпадает с шансом 40%, оплата — 60% работы, склад не тратится.
- **Исправлено:** коэффициент работы считался без базовой единицы и работа оплачивалась нулём; список деталей для замены не фильтровался по модели.
- **Баланс:** умный бот 170–219 дней (среднее ~187), казуальные 205–299 без банкротств.
- **Тесты:** 75 проверок.
